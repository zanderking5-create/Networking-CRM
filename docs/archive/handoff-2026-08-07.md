Written at the end of a long build session, for a fresh session doing an audit
and QA read. Everything below was verified against the working tree on the date

---

## 1. What this is

A single-user personal networking / job-search CRM. Next.js 16 (App Router,
RSC), Supabase (Postgres + auth), Tailwind v4, shadcn/ui on Base UI, deployed on
Vercel. `CLAUDE.md` in the repo root is the authoritative architecture doc —
read it first; it is detailed and current.

**One authenticated user. No multi-tenancy anywhere.** No `user_id` column, no
ownership checks. RLS is `for all to authenticated using (true)`, so the login
gate is the only thing protecting the data. Signups are disabled in Supabase and
must stay that way.

### What breaks if they haven't been run

Verify this before anything else — the failure modes differ in severity:

- **`/companies/[id]` → hard 500.** `listRolesForCompany` sits in the same
  `Promise.all` as `getCompany`, and that page has no try/catch. Every company
  detail page dies.
- **`/roles/[id]` → hard 500.** Same reason.
- **`/today` → whole page degrades.** All four queries share one `try`, so a
  single missing table replaces the entire dashboard with an error string, not
  just the affected section.
- Unaffected: `/contacts`, `/contacts/[id]`, `/companies` (list), `/capture`.

## 5. Known gaps and defects

Each of these was verified by grep/inspection on the date above.

**Correctness / robustness**
- `/today` has a single try/catch around a 4-way `Promise.all`. Any one failing
  query blanks the whole dashboard. Consider `Promise.allSettled` with
  per-section error states.
- `/companies/[id]` and `/roles/[id]` have no error handling at all, unlike the
  list pages (which deliberately catch and point at `supabase/migrations/`).
  That convention was not extended to the detail pages.
- `roles.status` has **no CHECK constraint** (deliberate, mirrors
  `tasks.status`). Only a `<select>` writes it. `lib/roles.ts` is the single
  source of truth for valid values.
- `listStalledRoles` filters `status=in.(in conversation,interviewing)` — one
  value contains a space. The generated PostgREST URL was inspected and is
  well-formed, but **this was never executed against a real database.** Verify
  it actually matches rows.

**Dead / unfinished**
- `interactions.role_id` and `tasks.role_id` exist in the schema and in
  `lib/db/types.ts` but **nothing reads or writes them.** Added so a future
  change wouldn't need another migration.
- `companies` still carries role-level columns —
  `founder_delegation_style`, `autonomy_scope`, `social_pct` — now duplicated on
  `roles`. Left in place intentionally pending a manual data migration. These
  are the drop candidates. **Do not drop `companies.conviction` or
  `companies.status`**: `listStalledHighConvictionCompanies` filters on
  conviction, and `/companies/[id]` still edits both.
- The capture flow (`lib/capture/`) knows nothing about `cadence` or `roles`.
  Deliberately deferred — the owner wants to feel out roles in the UI before
  deciding whether the LLM should create them.
- `tasks.status` comments claim `open | done | snoozed`, but nothing ever writes
  `snoozed`; snoozing just pushes `due_date`. The third state is not live.

**Missing product surface**
- **No sign-out anywhere in the app.** Verified: zero `signOut` calls. Once
  logged in there is no way out except clearing cookies.
- No dark mode toggle. `.dark` CSS variables are fully defined in
  `app/globals.css` but nothing ever sets the class.
- No search or filtering on contacts/companies.
- No manual interaction-creation UI; interactions only enter via `/capture`.

**Testing**
- **There is no test suite and no `test` script in `package.json`.** Zero
  automated coverage.
- `scripts/` is gitignored on purpose (some scripts prompt for the service-role
  key). It currently holds ~15 untracked ad-hoc verification scripts —
  ranking-math checks, PostgREST URL probes, Playwright screenshot helpers.
  Useful as prior art; not part of the build.

**Verification gap — read this carefully**
- Large parts of this app have **never been exercised against real
  authenticated data by me.** No login credentials were available and creating a
  test user was declined (signups are disabled by design; that's a real
  constraint, not an oversight). Verification was limited to typecheck, lint,
  build, pure-logic unit checks, PostgREST URL inspection, and screenshots of a
  temporary mock-data harness.
- Specifically unverified end-to-end: cadence Going-cold ranking against real
  rows, all roles CRUD, `status_changed_at` actually advancing on status
  change, the roles stall query matching rows, and every server action's
  write path.

## 6. Conventions that must not be broken

From `CLAUDE.md`, condensed. Violating these will look like a regression:

- **Server-rendered by default.** Every page under `app/(app)/` is an async
  Server Component calling `await requireUser()`. Only five client components
  exist and each is justified.
- **Mutations are plain server-action forms.** No client state, no optimistic
  UI, no fetch-from-client (except `/api/parse`). Show/hide uses
  `<details>/<summary>`, not `"use client"`.
- **Auth is enforced per page and per action** via `requireUser()`.
  `middleware.ts` only refreshes the cookie; it does not gate routes.
- **Never add signup/invite flows. Never loosen RLS.** The service-role key is
  never stored anywhere.
- **Visual system:** one shared row primitive (`components/ui/row.tsx`) for
  every list. Color signals meaning and only one meaning — conviction and warmth
  via olive `RatingDots`. Everything else neutral. Serif (`DisplayHeading`) is
  for major page headings only.
- `app/globals.css` carries a fix comment on `--font-sans`: it must point at the
  `next/font` variable, not itself. A circular value silently fell back to the
  browser's default serif app-wide once already — it took a screenshot to catch.
- **`lib/capture/schema.ts` must not be "simplified" into one schema.** The
  two-schema split is forced by hard constraints in Anthropic's structured
  outputs API. The file header documents each one.

## 8. Operational notes

- **Vercel auto-deploy stalled once mid-session** — two pushes landed on GitHub
  but never triggered builds. It recovered after a dashboard redeploy. If a
  push seems not to deploy, check Settings → Git before assuming a code problem.
- `vercel.json` pins the framework preset to `nextjs`. That pin fixed a
  404-on-every-route bug. Leave it alone.
- Env vars (`.env.local` and Vercel): `NEXT_PUBLIC_SUPABASE_URL`,
  `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `ANTHROPIC_API_KEY`.
- A `next dev` server may already be running on port 3000. Next 16 refuses to
  start a second one for the same directory — reuse it rather than fighting it.
- After moving route files (e.g. into a route group), a stale `.next` cache
  silently serves the old routing. `rm -rf .next` and restart. This cost real
  confusion once: the browser showed an entirely pre-redesign UI.
